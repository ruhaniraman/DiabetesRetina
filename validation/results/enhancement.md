# Does enhancement help the grading network? (Stage 1, enhanceForReview.m)

Generated by `stage1_quality/enhancementExperiment.m`. 149 held-out APTOS test photographs (30 per grade), full resolution, deployed Stage 3 model at its threshold 0.0964. Each photograph is degraded, then graded as is and after `enhanceForReview` (illumination normalisation, CLAHE, bilateral denoising).

| Condition | AUC as is | AUC enhanced | Sens / spec as is | Sens / spec enhanced |
|---|---|---|---|---|
| clean | 0.942 | 0.946 | 97.8% / 63.3% | 98.9% / 61.7% |
| darken x0.5 | 0.945 | 0.954 | 100.0% / 70.0% | 96.6% / 63.3% |
| darken x0.35 | 0.942 | 0.952 | 100.0% / 68.3% | 98.9% / 65.0% |
| blur (1 px at 224) | 0.951 | 0.921 | 100.0% / 46.7% | 91.0% / 75.0% |
| noise (sd 10) | 0.935 | 0.925 | 97.8% / 68.3% | 96.6% / 63.3% |

Specificity here is lower than in REPORT.md because the sample is enriched: 30 photographs per grade (29 Severe), so Mild eyes make up half of the non-referable group. Compare the columns, not these numbers with REPORT.md.

If "enhanced" is not clearly better, the app is right to grade the unprocessed photograph and to use the enhanced copy only for display. The network was trained on unprocessed photographs, so enhancement shifts its inputs away from what it learned.

**Result:** enhancement raises AUC slightly on darkened photographs (+0.009, +0.010) but lowers it on blurred (-0.030) and noisy (-0.010) ones, and moves the operating point (on blurred photographs sensitivity falls from 100% to 91%). So the network grades the unprocessed photograph; `enhanceForReview.m` is for display.
